# 🗂️ Manage Documentation Content in Strapi

The content model is now ready:

```text
Collection
└── Section
    └── Content
```

This guide shows how to populate that hierarchy through Strapi's **Content Manager**.

## Objective

By the end of this guide, you will be able to:

* Create a Collection.
* Create Sections within a Collection.
* Create Content entries within a Section.
* Add MDX documentation to `mdxContent`.
* Configure relationships correctly.
* Control the display order using `sortOrder`.
* Verify the complete hierarchy.

---

## Data Model at a Glance

For example:

```text
Collection
└── KnowledgeBase
    └── Section
        └── Strapi Production Pipeline
            ├── Create PostgreSQL Database in Neon
            ├── Set Up Strapi Backend
            ├── Design Content Model
            ├── Deploy Strapi to Render
            └── Configure Health Check
```

The important rule is:

```text
Collection → Section → Content
```

Create the hierarchy from the top down.

---

## Step 1 — Create the Collection 🧱

1. In the left sidebar, open **Content Manager → Collection** *(this is your "root" type)*
2. Click **Create new entry** (top right)
3. Fill in the fields:
    - **`name`** — e.g. `KnowledgeBase`
    - **`slug`** — auto-generates from the name; click the refresh (↻) icon to regenerate if you rename it
    - **`description`** — a short summary of what this Collection covers
    - **`mdxContent`** — Collection's homepage written in MDX/Markdown
    - **`sortOrder`** — controls display order if you have multiple Collections
4. Leave the **`sections`** relation field empty — you'll link Sections to it from the Section side
5. Click **Save**

   :::tip[Result]
   Your Collection now appears in the entry list with its **ID**, **name**, **slug**, and **description**.
   :::

---

## Step 2 — Create a Section 📑

1. Open **Content Manager → Section** *(this is your "Children" type)*
2. Click **Create new entry**
3. Fill in:
    - **`name`** — e.g. `Strapi Production Pipeline`
    - **`mdxContent`** — Section's homepage written in MDX/Markdown
    - **`slug`**, **`description`**, **`sortOrder`** — same as above
4. In the **`collection`** relation field, search for and select the Collection you created in Step 1 (e.g. `KnowledgeBase`) — this attaches the Section under that Collection
5. Leave **`contents`** empty — you'll populate it from the Contents side next
6. Click **Save**

   :::tip[Result]
   Once saved, the entry list will show **`collection (1)`** confirming the link back to its parent Collection.
   :::

---

## Step 3 — Create Each Piece of Contents 📝

1. Open **Content Manager → Content** *(this is your "Node" type)*
2. Click **Create new entry**
3. Fill in:
    - **`title`** — e.g. `Create the Postgres Database in Neon`
    - **`slug`** — auto-generated, regenerate if needed
    - **`description`** — short summary
    - **`mdxContent`** — the actual lesson/documentation body, written in MDX/Markdown
    - **`sortOrder`** — determines position within the Section
4. In the **`section`** relation field, select the Section this content belongs to (e.g. `Strapi Production Pipeline`)
5. Click **Save**
6. **Repeat** for every piece of content in that Section

   :::note[Example Batch]
   For a "Strapi Production Pipeline" section, you might create **5 entries**: Postgres/Neon setup, Backend setup, Content Data Model, Render deployment, and Health-check endpoint.
   :::

---

## Step 4 — Verify the Structure ✅

Go back to the Section entry **Section** and confirm:

- **`collection (1)`** shows the correct parent Collection linked
- **`contents (5)`** *(or however many you created)* lists every piece of Contents you attached, each with a drag handle (⠿) on the left

  :::tip[Sanity Check]
  This is your final check that the hierarchy nested correctly before you move on to the next Section.
  :::

:::caution[Common Pitfall]
Trying to create a Section before its Collection exists (or Contents before its Section) will leave you with nothing to select in the relation field. Always work **top-down**.
:::
